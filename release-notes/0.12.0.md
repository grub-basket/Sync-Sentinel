Recover notes that a network or cloud drive blanks out.

## The problem
Some network and cloud drives have a nasty failure mode: while Obsidian is
running, an open note's body gets suddenly wiped to empty on disk under the
editor. It isn't a sync conflict, no conflict file is written, and nothing
catches it — you just notice, sometimes much later, that notes are empty. This
has been a long-standing headache on shared and corporate drives.

## The recovery
With **version history** enabled, Sync Sentinel now guards against exactly this:

- It remembers each note's content **when you open it**, not only when you edit —
  so a pre-blank version exists even for a note you were only reading.
- When a save wipes a note's body, that empty version is recorded as
  **suspicious** — never used as good history or as a merge base, and it never
  displaces your last good version. You're alerted by a notice and a status-bar
  indicator, and the note is listed under *Blanked notes — recoverable* in the
  registry. Notes still blank after a restart are re-flagged on load.
- Recovery is **editor-aware and non-destructive**. Because the blanked note is
  still open, restoring writes into the editor (and flushes to disk) rather than
  writing the file underneath the loaded buffer — otherwise Obsidian would just
  re-save the blank over your recovered text. The current content is snapshotted
  first, so nothing is lost either way.

New commands: *Restore active note to last healthy version* and *Rescue blanked
notes now (open tabs)*, alongside the full version-history browser.

## Separated from syncing
Version history is now its own setting, independent of offline edit merging —
this failure has nothing to do with syncing, so the recovery works on a single
device with no sync at all. (Enabling offline edit merging still turns version
history on automatically.)
