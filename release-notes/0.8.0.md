First public release.

Sync Sentinel helps large files survive sync, and gives you safety nets around it.

## Large-file splitter
- Splits files at/above a threshold (default 200 MB) into sync-friendly shards
  (default 40 MB) and reassembles them byte-for-byte on your other devices.
- Every shard and the whole file carry a SHA-256 in a small synced manifest, so a
  corrupt or partial shard is rejected rather than silently written.
- Streaming I/O — memory stays flat regardless of file size.
- Auto-split and auto-reconstruct, with a registry view showing each file's state.
- Conflict policy: flag only, newest wins, or write a conflict file to compare;
  one-click resolution.

## Vault size overview
See your largest files, how close they are to the threshold, and which are over
or approaching it — before a file becomes a sync problem.

## Device tracking and space reclaim
- Each device keeps its own synced ledger (conflict-free) recording which files it
  holds; the command center shows who has what.
- Designate keeper devices that archive shards into a Sync-excluded folder.
- Purge is a suggestion queued for a keeper: only a keeper approves and executes,
  re-verifying its archive by hash first, and only once every active device holds
  the file (or has opted out of it).
- Per-file opt-out for devices that deliberately don't hold a file.

## Safety nets
- One-way generational backups with optional AES-256-GCM encryption; the key is
  stored in Obsidian's keychain (Secret Storage) when available.
- On-disk mirror of recently modified files, with short version history.
- Sync-log archiving, deduplicated by content hash.

## Syncthing / P2P mode
For vaults synced peer-to-peer, the plugin manages a `.stignore` block so the
keeper archive folder is excluded from Syncthing automatically.

Desktop only (uses Node filesystem APIs).
